# 技术细节

| 项 | 值 |
| --- | --- |
| 机器 | 小米 2510DRK44C（Redmi），Android 16 |
| 面板 | 1156 × 2510（自然方向竖屏），横屏逻辑 2510 × 1156 |

## 时间轴

```
H_n = h_obs − (L + λ) − t_ref + t_n
```

* `h_obs` 玩家第一次落指**被我们读到**的本机时刻
* `L + λ` 读取延迟 + 注入延迟（加载页里用 UHID 自点几下量出来，实测 ≈ 1ms）
* `t_ref` 玩家按中的那个音符的谱面时刻（默认第一个）
* `t_n` 第 n 个音符的谱面时刻

`L` 本身不影响精度（用的是内核时间戳），它只是让"开始发指令"晚一点。

## 触控注入（UHID）

```
类型 12  UHID_CREATE   注册设备：uid, name, HID 报告描述符
类型 13  UHID_INPUT    发报告：每指 1 字节状态 + 2 字节 X + 2 字节 Y，共 10 指
类型 14  UHID_DESTROY  注销
```

报告是**全量状态**：一次发的是所有手指的当前位置，所以"按下/移动/抬起"都靠改这一份
状态再发一次实现。手指编号 1..9（0 也可用），同一根手指在没抬起前不能被新音符复用。

## 坐标换算

真机触摸屏 `goodix_ts`（`/dev/input/event7`）报的是**面板自然方向**、单位 0.01 像素：

```
横屏 x = 竖屏 y        （0..2510）
横屏 y = 面板宽 − 竖屏 x  （0..1156）
```

谱面位置空间是 **24 格**，落点（1280×592 流坐标）：

```
center = position + size / 2
x(y)   = 639.5 + (center/12 − 1) × 0.831 × (y + 36.5)
判定线 y = 491.6（设备 y = 960）
```

该几何用实机录像与谱面对时验证过（命中 216/223 = 96.9%）。

## 手势模型

| 类型 | 动作序列 |
| --- | --- |
| tap | down → 40ms → up |
| long（原地） | down → 按住 → end+60ms → up |
| long（横移） | down → 沿轨迹按位移采样 move… → end+60ms → up |
| long（尾巴轻扫） | down → 跟随到尾巴位置 → 朝方向划 120px/50ms → up |
| long（头部轻扫） | 先划一段 → 回到条子位置按住 → 跟随 → up |
| flick（独立） | 提前 20ms down → 划 120px/50ms（up/left/right）→ up |

同一时刻的动作排序是**先按/移动、后松开**，避免游戏把"松手 + 新按下"并成一拍。

## 踩过的坑（省得再踩）

1. `sendevent` 被 SELinux 拒绝（`u:object_r:input_device:s0`）；旧代码用 subprocess
   吞掉了 stderr，所以一直"以为在点"。
2. `INJECT_TOUCH_EVENT` 的 `write_position` 字段顺序是 **x, y, width, height**，
   写错不报错，只是触点飞到屏幕外。
3. 屏幕静止时设备侧不发帧（编码器丢重复帧），所以取流只能用于有动画的画面。
4. `/proc/uptime` 是 BOOTTIME，和 getevent 的 MONOTONIC 不是同一个时钟。
5. **`cv2.imread` 在 Windows 上读不了含中文的路径**（静默返回 None）——
   脚本放在中文目录里就会认不出按钮。已改走 `imdecode + np.fromfile`。
6. 谱面长条的**中间节点有 2091 个不带 `position`**（头尾从不缺），
   要按时间在前后已知位置之间插值。
7. 长条尾巴/头部可能是 `type: flick`（尾 2512 / 头 200），只按住不划会掉。
